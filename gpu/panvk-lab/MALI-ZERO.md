# Mali Zero implementation plan

Deliver an app-local arm64 Vulkan driver for HyperWin. Start with the Pixel 6 Pro G78 Job Manager path. Qualify each additional GPU and kernel pairing independently. Keep the bundled driver selectable for rollback.

1. **Establish a buildable baseline.** Pin and audit the public FristOneRR source, license, Mesa ancestry, Android NDK, Meson options and dependencies. Build its unmodified Android shared library twice from clean directories, record hashes and dependency lists, and load it by explicit path with lab.sh. Compare it with the installed 3.7.0 binary as a separate reference. If the public tree cannot submit an offscreen job on raven, isolate the first failing initialization or submission step before importing optimizations. Keep Android kbase changes separate from Mesa compiler and Vulkan changes so each patch can be rebased.
2. **Identify hardware through the backend.** Log the GPU ID, revision, core mask and negotiated kbase ABI from the opened device. The Pixel reported 0x92020010 and its shell reported kernel 6.1.162-android14-11-g2ec90535fa34-ab15810641. Shell reads of gpuinfo and module version were denied. Validate the ID decode against kernel headers and model tables. Select submission layout from the negotiated ABI. Track Job Manager and CSF separately. Return an actionable unsupported-device result for an unknown interface.
3. **Prove the five DXVK features individually.** Extend the shell probe with a compute buffer readback and an offscreen triangle with a known pixel result. Add geometry amplification, per-viewport routing, clip and cull boundary cases, and sampled BC1–BC7 reference blocks including signed and sRGB variants. Check format properties, views, mip levels and array uploads. Evaluate the existing bcn_layer against native or internal decoding before choosing one decode path. Compare against independent expected results and relevant Vulkan CTS cases. Expose each feature only after its implementation passes. The existing compatibility override passing device creation establishes no rendering result.
4. **Separate backend and bridge failures.** First run native Vulkan, then the pinned project DXVK 3.1.1 D3D11 workload, then the same workload through guest WDDM. Capture adapter identity, feature level, result images and first failing stage. Include repeated device creation, queue/fence reuse, texture streaming, resize and teardown. Retain per-stage logs and confirm rollback works.
5. **Measure before selecting defaults.** Compare stock, shipped PanVK with and without its compatibility switch, and the candidate. Record unsupported workloads explicitly. Alternate driver order with matched resolution, scene, thermal state and cache state. Collect at least five runs per workload, cold pipeline creation time, warm median and p95 frame time, peak memory and thermal status. Profile the largest repeatable regression first. Repeat after sustained load. Require correct readbacks and zero device losses before interpreting speed. Promote an optimization only when its gain exceeds observed run-to-run variation and other supported workloads stay within baseline variation.
6. **Release by tested configuration.** Publish build inputs, patches, artifact hash and a matrix keyed by GPU revision, backend, kernel ABI and Android build. Start experimental on raven. Repeat correctness and performance tests on a second G78 SoC and a different supported Job Manager generation before broadening defaults. Qualify CSF separately when hardware and backend support are available. Deliver an opt-in package first, then enable by default only on qualified combinations.
